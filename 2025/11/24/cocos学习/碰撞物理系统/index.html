Cocos 碰撞与物理系统速查笔记

本笔记用于快速理解 Cocos Creator 2.x 与 3.x 中的
碰撞检测（Collision） 与 物理系统（Physics / Rigidbody） 的区别与使用方式。

一、碰撞基础概念

1️⃣ 碰撞发生的前提

  • 必须有碰撞体（Collider）
  • 至少 两个物体的碰撞体发生重叠

常见碰撞体类型：

  • BoxCollider（矩形）
  • CircleCollider（圆形）
  • PolygonCollider（多边形）

2️⃣ 分组与掩码（非常重要）

  • 碰撞体必须 分组匹配 才会检测到
  • 通过 Group / Mask 控制“谁和谁能碰撞”

📌 常见用途：

  • 子弹只打敌人，不打自己
  • UI 不参与物理碰撞
  • 触发器区域检测

二、Cocos Creator 2.x 碰撞系统

1️⃣ 纯碰撞检测（不需要物理效果）

✅ 只需要 Collider

  • 不需要 RigidBody
  • 不受重力、力、速度影响
  • 完全手动控制位移

📌 适合：

  • 点击检测
  • 技能范围
  • UI / 触发区域

2️⃣ 需要物理效果（反弹 / 重力 / 推动）

✅ 必须添加 RigidBody

  • 有重力
  • 有速度、加速度
  • 有物理反馈（弹开、滑动）

📌 适合：

  • 平台跳跃
  • 物体掉落
  • 弹球、推箱子

3️⃣ 2.x 碰撞回调示例代码

三、Cocos Creator 3.x 碰撞与物理系统

3.x 的设计思路 更接近 Unity

1️⃣ 核心规则（一定要记）

✅ 至少有一个物体挂 Rigidbody

📌 和 2.x 的最大区别就在这里

2️⃣ 3.x 中的组件关系

  • Collider：定义形状（Box / Sphere / Capsule）
  • Rigidbody：是否参与物理系统

3️⃣ 3.x 碰撞代码示例

四、Trigger（触发器） vs Collision（碰撞）

Trigger（只检测，不阻挡）

  • 勾选 IsTrigger
  • 不会产生物理反应

📌 适合：

  • 进入区域
  • 拾取道具
  • 检测范围

Collision（真实碰撞）

  • 不勾选 IsTrigger
  • 会产生物理阻挡和反馈

📌 适合：

  • 地面
  • 墙体
  • 实体物体

五、2.x 与 3.x 对比速查表

对比项 Cocos 2.x Cocos 3.x
纯碰撞检测 只要 Collider ❌ 默认不行
是否需要 Rigidbody 可选 至少一个必须
设计思路 轻量自定义 接近 Unity
推荐用法 UI / 技能 物理玩法

六、使用建议（面试高频总结）

  • 只想知道“碰没碰到”：用 Trigger
  • 需要反弹 / 掉落 / 推动：必须 Rigidbody
  • 2.x 项目：纯碰撞可以不加刚体
  • 3.x 项目：记住「至少一个 Rigidbody」

⭐ 一句话记忆版

  • 2.x：Collider 就能碰
  • 3.x：没 Rigidbody，不算碰

📌 非常适合：

  • Cocos 面试
  • 从 2.x 升级 3.x 的开发者
  • Unity 转 Cocos 的同学

七、碰撞系统接口（Cocos Creator 2.x 纯碰撞）

本节补充 CollisionManager 接口、Debug 绘制、底层回调数据结构，属于文档级 / 面试加分内容。

1️⃣ 获取并开启碰撞检测系统

📌 注意：

  • 不开启 enabled，onCollisionXXX 永远不会触发
  • 这是 2.x 新手最常见坑之一

2️⃣ 碰撞 Debug 可视化（强烈推荐）

📌 Debug 模式下可以看到：

  • 碰撞体真实形状
  • 世界坐标下的 AABB
  • 是否和你“以为的大小”一致

🔥 调试碰撞问题第一步：先开 DebugDraw

八、碰撞系统回调函数（核心）

当碰撞系统检测到碰撞时，会自动调用
挂在碰撞节点上的脚本函数

1️⃣ onCollisionEnter（碰撞开始）

📌 world 常用字段总结

字段 说明
aabb 当前帧世界包围盒
preAabb 上一帧包围盒
points 多边形 / Box 顶点
radius 圆形半径
position 圆心世界坐标

2️⃣ onCollisionStay（持续碰撞）

📌 常见用途：

  • 持续伤害（毒圈 / 激光）
  • 角色与地面接触检测

3️⃣ onCollisionExit（碰撞结束）

📌 常见用途：

  • 离开区域
  • 状态重置（离开地面 / 离开触发区）

九、点击检测（非物理，纯数学）

使用 Intersection 工具类 进行手动碰撞判断

1️⃣ 示例：点击是否命中碰撞体

2️⃣ Intersection 常用接口

接口 用途
pointInPolygon 点是否在多边形内
rectRect 矩形与矩形
circleCircle 圆与圆
polygonPolygon 多边形与多边形

📌 特点：

  • 不依赖物理系统
  • 性能可控
  • 非常适合 UI / 点击检测 / 技能范围

十、面试高频总结（可直接背）

  • 2.x 碰撞系统默认关闭，必须手动开启
  • DebugDraw 是排查碰撞问题的第一步
  • onCollisionEnter / Stay / Exit 生命周期非常清晰
  • Intersection 属于数学检测，不是物理系统

⭐ 一句话终极总结

碰撞 = Collider + Manager + 回调
物理 = Collider + Rigidbody + 物理世界

Cocos Creator 2.x 物理系统核心笔记

一、核心组件

1. 刚体组件 (RigidBody)

物理世界的实体，决定物体如何运动。

  • 组件名：cc.RigidBody
  • 作用：使节点参与物理模拟，受重力、力、碰撞影响。
  • 关键属性：type（刚体类型）、gravityScale（重力缩放）、linearVelocity（线性速度）。

2. 物理碰撞体组件 (PhysicsCollider)

定义物体的物理形状，用于碰撞检测。

  • 命名规则：Physics[Shape]Collider
  • 常见类型：
    • PhysicsBoxCollider：矩形碰撞体
    • PhysicsCircleCollider：圆形碰撞体
    • PhysicsPolygonCollider：多边形碰撞体
  • 与普通碰撞体区别：物理碰撞体以 Physics 开头，专用于物理系统；普通 BoxCollider 等用于碰撞系统，二者数据不互通。

二、刚体类型 (RigidBodyType)

类型 枚举值 说明 适用场景
Static (静态) cc.RigidBodyType.Static 质量无限大，完全静止。碰撞检测效率最高。 地面、墙体、静态障碍物
Dynamic (动态) cc.RigidBodyType.Dynamic 受物理定律影响（重力、力、碰撞）。质量、速度可设置。 箱子、球、角色（需精确物理模拟时）
Kinematic (运动学) cc.RigidBodyType.Kinematic 不受力影响，但可通过代码控制速度移动。能推动Dynamic物体。 移动平台、电梯、由代码控制的敌人
Animated (动画) cc.RigidBodyType.Animated 与Kinematic类似，但位置和旋转可通过动画（如Animation组件）驱动。 结合骨骼动画的物理物体

三、物理碰撞体 (PhysicsCollider) 详解

1. 通用属性

  • density (密度)：影响刚体质量。
  • friction (摩擦力)：0(光滑) ~ 1(粗糙)。
  • restitution (弹性)：0(无反弹) ~ 1(完全反弹)。
  • sensor (传感器)：设为 true 时，物体产生碰撞检测但无物理阻挡，用于触发区域。相当于触发器。

2. 与普通碰撞体 (cc.Collider) 的区别

特性 物理碰撞体 (PhysicsCollider) 普通碰撞体 (cc.Collider)
所属系统 物理系统，与 RigidBody 配合 碰撞系统，独立工作
依赖关系 通常需要 RigidBody 才能生效 可单独存在于节点上
物理效果 有真实的碰撞反作用力 仅做几何相交检测，无物理反馈
事件监听 碰撞事件：this.node.on(‘collision-enter’, …) 触发事件：this.node.on(‘trigger-enter’, …)
性能开销 较高（参与物理世界模拟） 较低（仅做数学计算）

四、工作流程

  1. 创建物理节点

    • 添加 RigidBody 组件，设置 type。
    • 添加 Physics[Shape]Collider 组件，调整形状、摩擦、弹性等。

  2. 控制与响应

    • 施加力：rigidBody.applyForce(force, point)
    • 设置速度：rigidBody.linearVelocity = cc.v2(x, y)
    • 监听事件：在脚本中监听物理碰撞事件。

  3. 分组管理

    • 在 项目设置 -> 物理碰撞矩阵 中设置哪些分组可以相互碰撞。

五、代码示例

六、重要提示

  1. 系统隔离：物理碰撞 (PhysicsCollider) 和普通碰撞 (cc.Collider) 是两套独立系统，它们之间不会发生任何碰撞检测。
  2. 单位注意：物理系统默认使用 米-千克-秒 (MKS) 单位制。1个单位长度=1米，合理设置重力（默认 -10 m/s²）和力的大小。
  3. 性能优化：
    • 静态(Static)刚体性能最优。
    • 简单形状（矩形、圆形）比多边形性能更好。
    • 不需要物理反馈时，使用传感器(sensor=true)或普通碰撞系统。
  4. 调试视图：在场景编辑器中点击 物理调试 按钮，可直观查看所有物理碰撞体的形状和刚体状态。
